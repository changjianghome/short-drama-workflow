## 3. 调用参数控制

调用时支持通过命令行参数（或搭配 JSON）进行控制：

### 3.1 配置文件 (`--json_file` / `-j`，高度推荐)
*   **作用**：一键从本地 JSON 文件中提取 `global_prompt`、`local_prompts`、`segment_lengths` 以及内部嵌套的 `frame_indices` 与 `strengths` 控制数组，自动完成 API Node 的映射。

> [!TIP]
> **JSON 规范参考**：如需生成满足本工作流格式要求与数据自洽性的 JSON 配置文件，建议使用并严格参照 **[ltx2.3-JSON生成规则.md](./ltx2.3-JSON生成规则.md)**（速查清单可参考 **[ltx2.3-JSON生成规则-硬性规定.md](./ltx2.3-JSON生成规则-硬性规定.md)**）。

#### 3.1.1 标准 JSON 结构示例及参数含义
如果使用 JSON 模式提交任务，您的 JSON 文件必须至少包含以下基础结构（额外的不相关字段会被脚本自动忽略）：

```json
{
  "global_prompt": "一个16岁的男孩在荒漠上，头顶是一片金属蓝色的天空...（全局背景、基调和人物特征设定）",
  "local_prompts": "男孩擦汗，镜头慢慢拉近 | 男孩叹气抱怨天气太热，画面无缝衔接 | 男孩转头看向远方",
  "segment_lengths": "176,176,144",
  "ltxv_add_guide_multi": {
    "frame_indices": [0, 176, 352],
    "strengths": [1.0, 0.95, 0.95]
  }
}
```

**JSON 参数详细说明：**
1. **`global_prompt` (字符串)**：全局提示词。负责奠定整个视频的环境、光影、人物外貌等不会轻易改变的全局设定。
2. **`local_prompts` (字符串)**：分段动作提示词。这是**核心驱动力**，使用竖线 `|` 符号进行切分。上方示例中被切分为了三段，分别对应三张图的独立动作控制。
   - **⚠️ 台词要求**：如果角色有台词语音，**必须将台词原文写入 local_prompts**，格式为 `She says '台词原文'` / `He says '台词原文'`。仅写 "speaking warmly" 或 "speaking" 等模糊描述，LTX 2.3 不会生成可识别的台词语音。
   - 正确示例：`Miss Li(女 teacher) smiles and says 'Welcome back to school, class.' audio: female teacher speaking clearly, classroom ambience`
3. **`segment_lengths` (字符串)**：分段帧数（时长）。用逗号 `,` 分隔。上方示例 `"176,176,144"` 代表：第一段跑 176 帧，第二段跑 176 帧，第三段跑 144 帧。脚本会自动将它们加总（496 帧）传给后端的总时长节点。
4. **`ltxv_add_guide_multi` (对象)**：多图序列打点引导控制（极度重要）：
   * **`frame_indices` (数组)**：各段参考图生效的“起始关键帧位置”。例如第一张图从第 `0` 帧开始，第二张图从第 `176` 帧（即第一段结束时）开始，第三张图从第 `352` 帧（176+176）开始。
   * **`strengths` (数组)**：各段参考图的引导强度（权重）。范围通常在 0 ~ 1.0 之间。通常首段给 `1.0`（完全贴合原图），后续承接段略微下降（如 `0.95`），给予模型一定的动画衍生自由度。

### 3.2 文本与引导控制 (可通过 JSON 自动填入)
*   **全局提示词 (`--global_prompt`)**：**节点 ID**：`1521`。
*   **分段提示词 (`--local_prompts`)**：**节点 ID**：`1522`，段落之间用 `|` 符号连接。
*   **分段时长 (`--segment_lengths`)**：**节点 ID**：`1507`，以逗号分隔的数字字符串（例如 `"176,176"`）。脚本会自动计算其总和提交给**总帧数节点** (`1508`)。
*   **帧打断点与强度 (`--frame_indice` / `--strengths`)**：**节点 ID**：`1509~1512` 以及 `1517~1520`。脚本会强制转换对应类型（int/float）。

## 4. 调用命令示例

### 4.1 ✅ 正确用法（V2.0 实战验证）

```bash
# 1. 必须设置两个环境变量：
#    - RH_ENV_PATH：指向 .env 文件路径（用于账号追踪）
#    - RUNNINGHUB_API_KEY：32位 API Key
export RH_ENV_PATH="<项目根>/.env"
export RUNNINGHUB_API_KEY="您的_32位_API_KEY"

# 2. 运行脚本（必须带 --project-dir 参数，不要用 --no-track-rh）
python3 scripts/ltx2.3_无导演台_纯参数.py \
  -j "wk/项目名/提示词/提示词_片01.json" \
  --image1 "wk/项目名/分镜图/片01.jpg" \
  -r "768x512 (3:2) (横屏)" \
  -o "wk/项目名/08_视频/片01.mp4" \
  --project-dir wk/项目名
```

### 4.2 ❌ 错误用法（会触发 414 错误）

```bash
# ❌ 错误：只设置 RUNNINGHUB_API_KEY，不用 RH_ENV_PATH
# ❌ 错误：用 --no-track-rh 代替 --project-dir
export RUNNINGHUB_API_KEY="您的_32位_API_KEY"
python3 scripts/ltx2.3_无导演台_纯参数.py \
  -j "..." --image1 "..." -r "768x512 (3:2) (横屏)" \
  -o "..." --no-track-rh
# 现象：提交尝试 1/10 失败: Unknown error (错误码: 414)
```

### 4.3 并行策略

*   单账号串行最稳；多账号可并行
*   并发上限建议 ≤ 4，否则会触发 421 队列限制
*   串行重试时 `sleep 5` 可避免 421

### 4.4 多账号轮换示例

```bash
# 账号 12 (568d055e... 600 RH) 用于视频生成
export RH_ENV_PATH="<项目根>/.env"
export RUNNINGHUB_API_KEY="568d055e..."
python3 scripts/ltx2.3_无导演台_纯参数.py \
  -j "提示词.json" --image1 "图.jpg" \
  -r "768x512 (3:2) (横屏)" -o "out.mp4" \
  --project-dir wk/项目名
```

## 附录：实战错误与正确用法（2026-07-30 Unit5_CartoonTime 实战）

### 错误码 414 - Unknown error

**现象**：
```
图片上传成功，云端路径: https://...
提交尝试 1/10 失败: Unknown error, please retry or contact support | 未知错误，请重试或联系支持 (错误码: 414)
无法提交任务，测试终止。
```

**真实原因**（实战排查 2026-07-30）：
- ❌ **不是**参数太长
- ❌ **不是**配额耗尽
- ❌ **不是**JSON 格式问题
- ✅ **是**调用方式错误：缺少 `RH_ENV_PATH` 环境变量 + 缺少 `--project-dir` 参数
- 使用了错误的 `--no-track-rh` 标志

**正确解决**：
```bash
# 必须：
export RH_ENV_PATH="<项目根>/.env"  # 账号追踪必须
export RUNNINGHUB_API_KEY="..."      # API Key
# 不要再用 --no-track-rh，改用：
python3 ... --project-dir wk/项目名
```

**对比成功 vs 失败**（同一脚本同一 JSON 同图）：

| 项目 | 错误用法 | 正确用法 |
|:---|:---|:---|
| 环境变量 | 只设 `RUNNINGHUB_API_KEY` | 设 `RH_ENV_PATH` + `RUNNINGHUB_API_KEY` |
| 参数 | `--no-track-rh` | `--project-dir wk/项目名` |
| 结果 | 414 Unknown error | SUCCESS + 下载到本地 |

### 错误码 421 - API queue limit

**现象**：
```
提交尝试 9/10 失败: api queue limit reached, please retry later (错误码: 421)
```

**原因**：
- 并行任务数超过 API 限制
- 脚本内置重试 10 次仍失败

**解决**：
- 降低并发数（建议 ≤ 4）
- 串行跑（每次 `sleep 5`）
- 多账号轮换（每个账号独立队列）

### 下载超时

**现象**：
```
下载失败: The read operation timed out
```

**解决**：手动用 `curl` 重试：
```bash
curl -L --max-time 120 -o "out.mp4" "https://rh-images-xxx.cos.ap-beijing.myqcloud.com/..."
```
